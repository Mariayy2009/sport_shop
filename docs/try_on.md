# Примерочная: установка и ограничения

В приложении два способа примерки. Оба бесплатные и не используют платные
облачные сервисы.

| | Примерка по фотографии | Живая примерка |
|---|---|---|
| Модель | FASHN VTON v1.5 (открытая, Apache-2.0) | Google ML Kit Pose Detection |
| Где работает | Ноутбук: локальный сервер FastAPI | Телефон: камера и модель позы |
| Нужен интернет | Только для установки | Нет |
| Нужен ноутбук | Да, включённый, в той же сети Wi-Fi | Нет |

## 1. Примерка по фотографии

### Почему нужен сервер на ноутбуке

Модель FASHN VTON весит около 2 ГБ и при работе занимает около 7 ГБ
оперативной памяти. На телефоне она не запустится, поэтому её запускает ноутбук, а
приложение отправляет ему два фото по домашней сети и получает результат.

### Проверка на оборудовании без видеокарты NVIDIA

Модель проверена на процессоре, без видеокарты (4 ядра x86, 16 ГБ памяти):

| Что | Результат |
|---|---|
| Загрузка модели при старте сервера | ~3 мин в первый раз, ~15 с при повторном запуске |
| Оперативная память в работе | 4,6 ГБ (было 7,2 ГБ до экономии памяти) |
| Один проход модели | ~31 с |
| Верх (майка, футболка): 4 шага по одному проходу | 2,2 мин |
| Низ (шорты, штаны): 4 шага, 7 проходов | 4,3 мин |
| Размер результата | 576 × 864 |

Проверено на трёх товарах каталога: «Баскетбольная форма» (верх),
«Шорты волейбольные» (низ) и футболка из примера модели — лицо, поза и
фон сохраняются, цвет и форма вещи переносятся. На 4–6 шагах мелкие
надписи могут исказиться (на майке «USC 31» получилось «ISC 11»);
для аккуратных надписей ставьте 10–12 шагов.

На вашем Intel Core 5 210H (8 ядер, 12 потоков) должно быть быстрее, чем на
тестовой машине с 4 ядрами, но это прогноз: на нём я не проверял. Нужно
16 ГБ памяти; во время генерации лучше закрыть браузер и другие тяжёлые
программы.
Встроенная графика Intel моделью не используется: PyTorch не умеет считать
на ней эту модель без отдельной конвертации.

**OpenVINO.** Для этой модели нет готовой конвертации в OpenVINO: это
нестандартная диффузионная модель (MMDiT), а не Stable Diffusion, для
которой у Intel есть готовые примеры. Конвертация — отдельное исследование
без гарантии ускорения, поэтому в проекте модель работает на обычном
PyTorch для процессора.

**Альтернативы, которые рассматривались.** CatVTON легче и имеет пример
для OpenVINO, но его лицензия CC BY-NC-SA запрещает коммерческое
использование — для интернет-магазина это не подходит. FASHN VTON v1.5
выбран как открытая модель с лицензией Apache-2.0 и поддержкой процессора.

### Установка на Windows (один раз)

1. Установите **Python 3.12** с [python.org](https://www.python.org/downloads/).
   В установщике отметьте «Add python.exe to PATH».
2. Откройте папку проекта `tryon_server` и запустите **`setup_windows.bat`**.
   Он создаст окружение, поставит PyTorch для процессора, библиотеки и
   скачает веса модели (около 2 ГБ). Это занимает 10–20 минут.

Нужно около 6 ГБ на диске.

### Запуск

1. Запустите **`run_server.bat`**. При первом запуске модель загружается
   около 3 минут, потом — секунды.
2. В окне появится строка:
   `Сервер примерки запущен. Адрес для приложения: http://192.168.1.5:8000`
3. Windows спросит разрешение для Python в брандмауэре — разрешите доступ
   **в частных сетях**. Без этого телефон не достучится до сервера.

Окно не закрывайте, пока пользуетесь примеркой.

Количество шагов генерации задаётся в `run_server.bat`: `TRYON_STEPS=4`.
При запуске сервер сам проверяет, со сколькими потоками процессор
считает быстрее (у Intel с быстрыми и медленными ядрами это не всегда
«все ядра»), и пишет выбор в окне.
Каждый шаг — примерно минута на процессоре; 10–12 шагов аккуратнее
передают надписи и логотипы.

### Подключение телефона

1. Телефон и ноутбук — в **одной сети Wi-Fi**. Гостевые и публичные сети
   часто запрещают устройствам видеть друг друга.
2. В приложении: карточка товара → «Примерить» → «Примерить по
   фотографии» → строка «Сервер примерки не подключён».
3. Введите адрес из окна сервера, например `192.168.1.5:8000`, и нажмите
   «Подключить». Приложение сразу проверит связь.

**Эмулятор Android** на том же ноутбуке видит его по адресу `10.0.2.2:8000`.

**Память — главное условие скорости.** Если в Диспетчере задач память
занята больше чем на 90%, Windows сбрасывает её на диск, и шаг идёт в
4–5 раз медленнее. Поэтому сервер хранит веса модели компактно
(bfloat16, разворачивает по одному слою) и считает варианты шага по
очереди. Перед примеркой закройте браузер и эмулятор Android.

**Верх считается быстрее.** Для верха шаг делается одним проходом
модели вместо двух — результат почти не отличается (проверено на
майке). Для шорт и штанов второй проход нужен: без него ноги
размываются. Отключить ускорение: `set TRYON_FAST_TOPS=0` в
`run_server.bat`.

Пока идёт примерка, сервер запрещает ноутбуку засыпать (экран может
погаснуть — это не мешает) и отключает для себя режим экономии энергии
Windows. Ход работы видно в окне сервера: «шаг 2 из 6 (75 с)».
Лучше держать ноутбук **на зарядке**: от батареи процессор считает
медленнее.

Если примерка долго стоит «в очереди» — значит, ноутбук ещё считает
прежнюю. Новая примерка с того же телефона отменяет прежнюю
автоматически.

Если не подключается:
- проверьте, что окно сервера открыто и в нём нет ошибок;
- в браузере телефона откройте `http://<адрес>:8000/health` — должен
  прийти ответ со словом `model_ready`;
- проверьте разрешение в брандмауэре Windows (частные сети);
- узнайте IP ноутбука командой `ipconfig` (строка «IPv4-адрес»
  у адаптера Wi-Fi).

### Какие фото подходят

- **Фото человека:** в полный рост или по пояс, лицом к камере, хороший
  свет, одежда не мешковатая. Минимум 256 пикселей по меньшей стороне,
  до 15 МБ, JPG/PNG/WebP.
- **Фото товара** берётся из каталога автоматически. Лучше всего работают
  каталожные фото одной вещи целиком на однотонном фоне. Если на фото
  товара несколько вещей или вещь снята крупным планом, результат будет
  хуже.

### Безопасность фото

- Фото уходят только на ваш ноутбук, не в интернет.
- Сервер держит фото в памяти только на время генерации и не пишет их на
  диск. Результат удаляется с сервера сразу после получения, а
  неполученный — через 30 минут.
- На телефоне последнее фото и сохранённые примерки лежат в закрытой
  папке приложения. Кнопка «Удалить моё фото и примерки» стирает всё.

## 2. Живая примерка

Работает на телефоне с Android или iOS, без сервера и интернета.

**Два режима.**
- **Фото вещи** (по умолчанию): вещь вырезается из фото товара (фон
  убирается заливкой от краёв кадра) и накладывается на тело по плечам
  или бёдрам — с настоящим принтом, номером и надписями. Работает для
  каталожных фото на однотонном фоне; если вещь снята на человеке —
  включается 3D.
- **3D-модель**: упругая модель вещи следует за руками и ногами.

**Размер.** Под камерой — размеры товара. Рекомендуемый по росту
и весу из профиля отмечен зелёной рамкой. Размер больше — вещь на теле
шире и длиннее (на 8% за каждый размер), меньше — уже и короче;
подпись подсказывает: «Советуем M. Размер XL будет: велико».

**Чего нет.** Своя одежда под вещью не стирается: для этого нужна
генеративная нейросеть, она работает в примерке по фото (на ноутбуке),
а не в реальном времени на телефоне.

Чтобы вещь выглядела надетой, а не наклеенной, используются ещё две
вещи из кадра камеры:

- **Силуэт** — Google ML Kit Selfie Segmentation (на телефоне) находит
  человека в кадре, и края вещи обрезаются по настоящему контуру тела.
- **Свет и складки** — яркость кадра на теле сравнивается с соседними
  точками: тени и складки своей одежды переносятся на новую вещь
  (наложение hardLight). Общий цвет своей одежды не важен — белая
  футболка и тёмная кофта дают одинаковый результат.

1. Камера (по умолчанию фронтальная) передаёт кадры модели Google ML Kit
   Pose Detection — она находит плечи, локти, запястья, бёдра, колени и
   щиколотки.
2. По суставам строится «скелет» одежды: торс от плеч к бёдрам, рукава
   вдоль рук, штанины вдоль ног, с поворотом корпуса и глубиной.
3. Низкополигональная 3D-модель вещи (GLB, 170–400 треугольников)
   изгибается по этим костям, освещается и рисуется поверх кадра каждый
   раз, когда приходит новая поза. Цвет берётся с фото товара.

Вещь можно сменить лентой внизу, не закрывая камеру. Кнопка с фигуркой
показывает найденные точки тела.

На компьютере камеры и ML Kit нет — там открывается предпросмотр 3D-модели
на условной движущейся фигуре с подписью об этом.

### 3D-модели

Модели лежат в `assets/models/*.glb` и генерируются скриптом
`tools/make_garments.py` (без сторонних библиотек). Это собственные модели,
лицензионных ограничений нет: футболка, игровая майка, лонгслив/кимоно,
шорты, штаны.

Готовые бесплатные GLB-модели спортивной одежды в открытом доступе обычно
сделаны под конкретный скелет аватара и весят мегабайты; для посадки по
12 точкам ML Kit их пришлось бы переделывать. Свои модели устроены
проще: каждая часть привязана к одной кости тела.

## Ограничения

**Примерка по фотографии**
- Генерация на процессоре занимает минуты; на ноутбуке с видеокартой
  NVIDIA сервер сам перейдёт на неё и будет считать в разы быстрее.
- Ноутбук должен быть включён и в той же сети, что и телефон.
- Сервер обслуживает одну примерку за раз, остальные ждут в очереди.
- Модель обучена на одежде: обувь и аксессуары она не надевает.
- Для низа (шорты, штаны) сервер сначала стирает исходную одежду на фото
  маской — иначе шорты нарисовались бы поверх длинных брюк. Для верха
  маска не нужна, так лучше сохраняется фигура.
- На качество сильно влияет фото товара (см. выше).

**Живая примерка**
- Это технический MVP, а не реалистичная ткань: модель одежды — упругая
  оболочка вокруг «костей», без складок, физики ткани и учёта формы тела.
- Цвет вещи однотонный: основной оттенок с фото товара (фон и надписи
  не учитываются). Принт, номера и логотипы не переносятся — для этого
  нужна отдельная 3D-модель каждого товара с текстурой.
- Вещь видна только в пределах силуэта тела: свободный крой, который
  отходит от тела, обрезается по контуру.
- Глубина в ML Kit приблизительная, поэтому повороты корпуса больше
  50–60° отображаются неточно; руки перед телом могут перекрываться
  неверно.
- В кадре должны быть плечи и бёдра; для шорт и штанов — ещё и ноги.
- Поза обновляется с частотой модели ML Kit (на среднем телефоне
  примерно 10–25 раз в секунду).
