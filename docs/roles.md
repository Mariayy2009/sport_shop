# Роли: покупатель, продавец, администратор

| Что | Покупатель | Продавец | Администратор |
|---|---|---|---|
| Покупать, корзина, заказы, отзывы, вопросы | ✓ | ✓ | ✓ |
| Выставлять свои товары, менять и удалять их | | ✓ (только свои) | ✓ (любые) |
| Отвечать на вопросы покупателей | | ✓ (о своих товарах) | ✓ (о любых) |
| Статус заказа и «где товар» | | ✓ (заказы со своими товарами) | ✓ (все заказы) |
| Снимать товар с продажи | | | ✓ |
| Предупреждать продавца | | | ✓ |
| Читать предупреждения | | ✓ | |
| «Зал славы»: экспонаты | | | ✓ |

## Своё приложение у каждой роли

Нижние вкладки зависят от роли — покупательские разделы продавцу
и администратору не нужны и только путают:

| Роль | Вкладки |
|---|---|
| Покупатель | Главная · Каталог · Помощник · Корзина · Профиль |
| Продавец | Главная · Каталог · **Сканер** · **Кабинет** · Профиль |
| Администратор | Главная · Каталог · **Модерация** · **Продавцы** · Профиль |

В профиле продавца и администратора нет «ИИ-помощника» и «Моего
комплекта».

## Продавец

Вкладка **«Сканер»** — отсканировать свою вещь для живой примерки
(см. ниже). Вкладка **«Кабинет»** (или Профиль → «Кабинет продавца»):
- **Мои товары** — выставить новый товар (бренд — название магазина),
  изменить или удалить свой. Снятые администратором товары помечены
  красным с причиной.
- **Заказы** — заказы, где есть его товары: статус (новый / в пути /
  доставлен) и **«Где товар»** — текст, который покупатель видит в своём
  заказе: «Отправлен из Алматы, привезём 27 ноября».
- **Вопросы** — вопросы покупателей о его товарах; ответ подписан
  «Ответ продавца …». Ответить можно и прямо в карточке товара.
- **Предупреждения** — от администратора: причина, товар, пояснение.

В карточке товара покупатель видит **«Продавец: Budo Pro»**
(товары без продавца продаёт сам магазин SPORT).

## Сканер примерки

1. Продавец выбирает свою одежду (футболка, форма, кимоно, шорты, штаны).
2. Надевает её, ставит телефон вертикально, встаёт в полный рост
   и медленно поворачивается на 360°.
3. По позе в каждом кадре приложение понимает сторону: плечи широкие
   и лицо видно — перед, лица не видно — спина, плечи узкие — бок.
   Прогресс: перед → бок → спина → другой бок.
4. Лучшие кадры спереди и сзади вырезаются по силуэту человека
   (ML Kit Selfie Segmentation), запоминается, где плечи и бёдра.
5. Экран **«Обработка создания примерки»** (~10 с, этапы) — для продавца.
6. Покупатель в живой примерке сразу видит вещь, снятую на человеке:
   с настоящими складками и посадкой, а повернувшись спиной — спинку.
   Для покупателя ожидания нет.

Это две «фотографии на человеке» (перед и спина) с точной посадкой,
а не полная 3D-модель: настоящей 3D-реконструкции вещи с телефона
без сервера с видеокартой не сделать.

## Администратор

Вкладка **«Модерация»** (или Профиль → «Панель администратора»):
- **Товары** — у каждого товара меню: изменить, **снять с продажи** /
  вернуть в продажу, **предупредить продавца**. Причины: запрещённый
  товар, подозрение на мошенничество, неверное описание или фото,
  завышенная цена, другое — плюс пояснение. Снятый товар пропадает из
  каталога, поиска и подбора; продавцу автоматически приходит
  предупреждение.
- **Заказы** — все заказы: статус и «где товар».
- **Вопросы** — все вопросы: ответить или удалить.

Вкладка **«Продавцы»** — все магазины: сколько товаров, сколько снято
с продажи, сколько предупреждений; «Предупредить магазин» и история
предупреждений.

## Как устроено в базе

- `sellers (user_id, shop_name)` — магазин пользователя: пользователь
  с магазином — продавец (в `users.role` он хранится как `customer`, так
  обновление базы не трогает таблицу пользователей).
- `products.seller_id`, `products.status` (`active` / `blocked`),
  `products.block_reason`.
- `orders.tracking_note` — «где товар».
- `seller_warnings` — предупреждения продавцам.

Обновление базы до версии 12 добавляет колонки и таблицы — корзина,
заказы и избранное сохраняются.

Пока это работает на данных телефона; на сервере PostgreSQL роли
появятся вместе со входом через сервер (шаг 2 перехода).

## Уведомления и новые поля товара

* **Кружочки у продавца.** На вкладке «Кабинет» и на вкладках «Вопросы» и
  «Предупреждения» — красный счётчик: непрочитанные предупреждения
  администратора (в том числе «товар снят с продажи») и вопросы без ответа.
  Проверяется при входе и раз в 30 секунд; пропадает, когда продавец открыл
  вкладку или ответил (`lib/state/seller_badge_state.dart`).
* **«Для всех видов спорта».** Вид спорта для бутылок, рюкзаков, спортивного
  питания: такой товар виден в каталоге каждого спорта. В витрине, фильтрах
  и анкетах этого пункта нет — только в форме товара.
* **«Состав»** (`products.composition`, база v15, сервер — миграция 0004) —
  для протеина и другого спортивного питания; новая категория
  «Спортивное питание». Показывается отдельным блоком в карточке товара.
* **Уведомления.** После добавления/правки товара — «появится в каталоге через
  несколько секунд»; после снятия с продажи — «пропадёт из каталога в течение
  минуты», каталог «Товары» обновляется сразу.

## Этап v16: уведомления, статистика, рекорды, спортпит

* **Уведомления** (`notifications`, экран «Профиль → Уведомления», кружок на
  «Профиле»): продавец ответил на вопрос; заказ в пути / доставлен / «где
  товар»; товар из корзины сняли с продажи; промокод за игру. Продавцу —
  «товар заканчивается» (остаток ≤ 3 после заказа).
* **Корзина**: снятые с продажи и раскупленные позиции подсвечены, оформить
  заказ с ними нельзя, есть кнопка «Убрать недоступные товары».
* **Статистика продавца** — первая вкладка кабинета: выручка за месяц и всего,
  проданные штуки, заказы, топ-5 товаров.
* **Остатки**: плашка «Осталось N шт.» на карточках, «Мало осталось» в товаре,
  «Заканчивается» в «Моих товарах» продавца.
* **Отзывы**: «Покупатель подтверждён», если автор заказывал товар
  (`reviews.verified`). Оставить отзыв можно только после доставки.
* **Игра**: результаты вошедших игроков сохраняются (`game_scores`), таблица
  рекордов по режимам; за 10 касаний — промокод 5% на мячи (`coupons`),
  вводится при оформлении заказа (`orders.discount`).
* **Спортпит**: отметки «Без лактозы / Веган / Без сахара» (`products.diet`) в
  форме продавца и в фильтрах; калькулятор порций протеина по весу и цели —
  если в составе написано «В порции 30 г — 24 г белка». Демо-товары магазина
  Sportlife: сывороточный и растительный протеин, изотоник (картинки —
  простые иллюстрации, их можно заменить настоящими фото).
* Сервер PostgreSQL: миграции 0004 (`composition`) и 0005 (`diet`).

## Этап v17: заказы админа, заморозка и удаление продавцов, апелляции

* **Заказы у администратора.** Администратор ведёт (статус, «где товар») только
  заказы с товарами самого магазина SPORT — у них нет продавца. Заказы
  продавцов он видит только для чтения: чтобы разобрать жалобу покупателя.
* **Заморозка** (`sellers.status = 'frozen'`): товары магазина скрыты из
  каталога, купить их нельзя (в том числе из корзины), выставлять новые
  нельзя. Автоматически — после 3 предупреждений подряд (счёт с последней
  разморозки) или вручную с причиной.
* **Удаление** (`'deleted'`) — крайняя мера: выбор причины, подробное
  объяснение (от 15 символов), ввод названия магазина и подтверждение
  «Вы уверены?». Данные не стираются — магазин можно восстановить.
* **Апелляции** (`seller_appeals`): продавец пишет из кабинета, администратор
  получает уведомление и видит апелляции вверху вкладки «Продавцы»; принять —
  магазин снова работает, отклонить — с обязательной причиной. Ответ приходит
  продавцу в «Уведомления».

## Этап v18: автопроверка товаров

`lib/services/moderation/content_checker.dart` — правила (без нейросети и
интернета), `lib/data/datasources/local/product_screening.dart` — запуск при
каждом сохранении товара. Что ищется:

* запрещённые слова — наркотики, допинг, оружие, лекарства без рецепта —
  в том числе разбитые пробелами/точками («м е ф»), с латинскими буквами
  вместо русских («мeфeдpoн»), с невидимыми символами;
* контакты для сделки вне магазина (Telegram, WhatsApp, @ник, телефон,
  ссылки, криптовалюта);
* эмодзи-коды (❄ 🍁 🌿 💊 🍄 💉 …);
* цена в 4 раза ниже или в 5 раз выше обычной в категории;
* находка в последней пятой части длинного описания помечается
  «спрятано в конце описания».

60+ баллов у товара продавца — скрыт до решения администратора
(`products.moderation = 'pending'`), 25+ — в продаже, но в очереди
(`'flagged'`). Администратор: вкладка «Модерация → Проверка», находки
показаны с кусочком текста; «Всё в порядке» или «Снять с продажи»;
«Проверить весь каталог». Продавцу и администраторам — уведомления.

## Этап v19: каталог по вариантам, магазин продавца, корзина с галочками, усиленная автопроверка

* **Каталог:** каждый вариант товара (цвет, модель) — отдельная карточка со
  своим фото; карточка открывает товар сразу на этом варианте, внутри варианты
  по-прежнему переключаются. Запрос «синяя капа» показывает только синие.
* **Магазин продавца** (`ShopScreen`, маршрут `/shop`): из карточки товара по
  ссылке «Продавец»; рейтинг магазина по отзывам, число отзывов и товаров, все
  товары, отзывы о товарах магазина. У товаров без продавца — магазин SPORT.
* **Корзина:** галочки у товаров и «Выбрать все»; в заказ идёт только
  отмеченное, остальное остаётся в корзине.
* **Таблица размеров** показывается только у товаров с размерами.
* **Автопроверка:**
  - латиница «на слух» (`porosho.k` = «порошок», `mefedron` = «мефедрон»);
  - иносказания («белый порошок», «белые кристаллы»);
  - «синтетика» и дробные граммы у спортивного питания;
  - проверяются материал и бренд;
  - **отзывы и вопросы покупателей:** «наркоши», «закладки», «обман» — товар
    уходит в очередь администратора (не скрывается: отзыв может написать
    конкурент);
  - **текст на фото** (ML Kit Text Recognition на телефоне): ник канала,
    ссылка, телефон в углу фото — `products.photo_text`, база v19;
  - много покупок товара продавца за сутки (5+).

## Этап v20: SPORT — продавец, администратор только модерирует, документы и данные продавцов

* **Магазин SPORT** — обычный продавец (`sport@sport.kz`), ему принадлежат
  товары, у которых раньше не было продавца; он сам выставляет товары и ведёт
  их заказы. Администратор товары не создаёт и не правит, заказы видит только
  для разбора жалоб.
* **Документы** (`lib/core/legal/legal_documents.dart`, экран «Правила и
  документы» в профиле): Пользовательское соглашение, Политика
  конфиденциальности, Правила для продавцов. Ссылки — на экране регистрации.
  Тексты — шаблон учебного проекта, перед запуском их проверяет юрист.
* **Данные продавца** (`sellers.legal_*`, `iin`, `agreed_at`,
  `rules_version`): форма (ИП / ТОО / самозанятый), ИИН или БИН с проверкой
  контрольной цифры, ФИО/наименование, телефон, юридический адрес и три
  согласия (правила; только разрешённые и сертифицированные товары; передача
  данных в правоохранительные органы при признаках преступления). Без них
  нельзя выставлять товары. Покупатель может «Стать продавцом» из профиля.
* **Сертификат** (`products.certificate`): для спортивного питания номер
  сертификата или декларации обязателен; показывается в карточке товара.
* **Материалы для полиции** (`law_reports`): администратор формирует документ
  (данные продавца, товары с находками автопроверки, заказы, предупреждения),
  копирует и передаёт официально; факт подготовки записывается в журнал.
  Приложение само никуда данные не отправляет.
* **Каталог «Рекомендуем»** — карточки вперемешку, варианты одного товара не
  стоят рядом; галочка «в корзине» — только у положенного варианта.
